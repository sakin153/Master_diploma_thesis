# Батчевая генерация графа сцены

## Проблема

При генерации больших сцен (например, 6 столов × 4 стула = 30 объектов) LLM сталкивается с проблемами:

1. **Обрезание JSON** - достигается лимит токенов (`num_predict`), и JSON обрывается
2. **Китайские символы** - модель `deepseek-v3.1` иногда вставляет китайские символы вместо английских
3. **Невалидный JSON** - из-за обрезания или ошибок генерации

## Решение

Реализована **батчевая генерация графа сцены** в `project/scene_planner.py`:

### Алгоритм

1. **Классификация объектов** (`_classify_objects_by_role`)
   - Разделяет объекты на **якоря** (столы, диваны) и **зависимые** (стулья, тарелки)
   - Использует эвристику на основе ключевых слов

2. **Генерация якорей батчами** (`_build_anchor_nodes_batch`)
   - Генерирует якорные узлы порциями по **10 штук**
   - Каждый батч - отдельный запрос к LLM
   - Fallback на эвристику при ошибках

3. **Генерация зависимых объектов батчами** (`_build_dependent_nodes_batch`)
   - Генерирует зависимые узлы порциями по **15 штук**
   - Привязывает к уже созданным якорям
   - Fallback на эвристику при ошибках

4. **Объединение в граф**
   - Все узлы объединяются в единый граф
   - Вычисляются уровни иерархии
   - Валидация и размещение anchor позиций

### Преимущества

✅ **Универсальность** - работает для любых запросов (не только столы+стулья)
✅ **Масштабируемость** - может генерировать сцены с 50+ объектами
✅ **Надежность** - fallback на эвристику при ошибках LLM
✅ **Детерминизм** - эвристические fallback'и дают предсказуемые результаты

### Параметры батчей

Можно настроить в коде:

```python
# В _build_anchor_nodes_batch
batch_size=10  # Якорей в одном запросе

# В _build_dependent_nodes_batch
batch_size=15  # Зависимых объектов в одном запросе
```

## Улучшения в llm_request.py

1. **Увеличен лимит токенов**: `num_predict: 2000 → 4000`
2. **Улучшен парсинг JSON**:
   - Обработка незакрытых markdown блоков
   - Поиск JSON в тексте
   - Обрезка лишнего текста после JSON
3. **Фильтрация китайских символов** (`_sanitize_json_string`):
   - Заменяет известные проблемные символы
   - `"anchor_h极"` → `"anchor_hint"`
   - `"极"` → `"facing"`
4. **Логирование для отладки**:
   - Вывод первых/последних 500 символов при ошибке
   - Точное место ошибки парсинга

## Пример запроса

```python
query = "6 столов у каждого стола по 4 стуля"
# Результат: 6 якорей (столы) + 24 зависимых (стулья) = 30 объектов
```

## Структура графа

```json
{
  "nodes": [
    // Якоря (level 0)
    {"id": "table_1", "level": 0, "parent_id": null, ...},
    {"id": "table_2", "level": 0, "parent_id": null, ...},
    ...
    // Зависимые объекты (level 0, но с relationship)
    {"id": "chair_1", "level": 0, "parent_id": null, 
     "relationship": {"type": "around", "reference": "table_1", ...}},
    {"id": "chair_2", "level": 0, "parent_id": null,
     "relationship": {"type": "around", "reference": "table_1", ...}},
    ...
  ]
}
```

## Известные ограничения

1. **Эвристика классификации** - может неправильно определить якоря для нестандартных объектов
2. **Размер батчей** - фиксированный, не адаптируется к сложности объектов
3. **Fallback** - эвристический fallback создает простую сетку, может не соответствовать запросу
