# Bugfix Requirements Document

## Introduction

Система размещения объектов Universal Placement System имеет критические проблемы с размещением объектов в 3D сценах. При создании сцен с вложенными объектами (например, "стол и две коробки на нем в каждой коробке по 3 яблока") наблюдаются следующие дефекты:

1. **Объекты "зависают" в воздухе**: Объекты, которые должны быть динамическими и падать под действием гравитации, остаются зафиксированными в пространстве
2. **Коллизии между объектами**: Объекты на одной поверхности (например, коробки на столе) пересекаются друг с другом
3. **Неправильное позиционирование вложенных объектов**: Объекты, которые должны быть внутри контейнеров (яблоки в коробках), размещаются смещенными к краю контейнера вместо центра

Эти проблемы делают сгенерированные сцены физически некорректными и непригодными для симуляции.

## Bug Analysis

### Current Behavior (Defect)

**1. Объекты зафиксированы в пространстве (не падают)**

1.1 WHEN LLM генерирует семантический план с объектами, которые должны быть динамическими (яблоки, мелкие предметы) THEN LLM может неправильно установить `is_static=true` или вообще не указать это поле

1.2 WHEN система обрабатывает семантический план в `universal_system.py` THEN она может игнорировать или неправильно применять значение `is_static` из плана

1.3 WHEN генерируется сцена с промптом "стол и две коробки на нем в каждой коробке по 3 яблока" THEN яблоки висят в воздухе и не падают в коробки из-за `is_static=true`

**2. Коллизии между объектами на одной поверхности**

1.4 WHEN система размещает несколько объектов на одной поверхности (например, две коробки на столе) THEN объекты частично входят друг в друга (пересекаются)

1.5 WHEN проверка коллизий выполняется в `layout_solver.py` или `universal_system.py` THEN проверка не обнаруживает пересечения или не применяет корректировки

**3. Неправильное позиционирование вложенных объектов**

1.6 WHEN система размещает объекты внутри контейнеров (яблоки в коробках) THEN объекты размещаются смещенными к краю контейнера вместо центра

1.7 WHEN объекты должны упасть в контейнер при симуляции THEN из-за смещения они падают мимо контейнера или застревают на краю

### Expected Behavior (Correct)

**1. Динамические объекты должны падать**

2.1 WHEN LLM определяет, что объект должен быть динамическим (яблоки, мелкие предметы, контейнеры) THEN система SHALL установить флаг `is_static=false` для этого объекта

2.2 WHEN система обрабатывает метаданные объектов в `universal_system.py` THEN она SHALL корректно применять значение `is_static` из семантического плана, сгенерированного LLM

2.3 WHEN генерируется сцена с вложенными объектами THEN динамические объекты SHALL быть размещены над поверхностью и падать под действием гравитации при симуляции

2.4 WHEN LLM не указывает явно значение `is_static` для объекта THEN система SHALL использовать эвристику (volume < 0.3 m³ или тип "контейнер") только как fallback механизм

**2. Объекты не должны пересекаться**

2.5 WHEN система размещает несколько объектов на одной поверхности THEN она SHALL проверять коллизии между объектами с использованием OBB (Oriented Bounding Box)

2.6 WHEN обнаружена коллизия между объектами THEN система SHALL скорректировать позиции объектов, чтобы устранить пересечение

2.7 WHEN используется `check_collisions()` в `physics.py` THEN функция SHALL корректно обнаруживать пересечения с учетом размеров объектов

**3. Вложенные объекты должны быть центрированы**

2.8 WHEN система размещает объект внутри контейнера (constraint type: "inside" или "containment") THEN объект SHALL быть размещен в центре контейнера по осям X и Y

2.9 WHEN объект размещается над контейнером для последующего падения THEN высота Z SHALL быть установлена так, чтобы объект гарантированно упал внутрь контейнера

2.10 WHEN вычисляется позиция для constraint "inside" THEN система SHALL использовать центр bounding box контейнера, а не случайную точку

### Unchanged Behavior (Regression Prevention)

**1. Статические объекты остаются статическими**

3.1 WHEN объект является мебелью или крупным предметом (стол, стул, шкаф) THEN система SHALL CONTINUE TO устанавливать `is_static=true`

3.2 WHEN объект имеет большой объем (volume ≥ 0.3 m³) THEN система SHALL CONTINUE TO считать его статическим по умолчанию

**2. Размещение объектов без вложенности**

3.3 WHEN объекты размещаются на полу без вложенности THEN система SHALL CONTINUE TO использовать существующую логику размещения

3.4 WHEN используются constraints типа "near", "on", "region" THEN система SHALL CONTINUE TO обрабатывать их с существующей логикой

**3. Общий пайплайн генерации**

3.5 WHEN генерируется сцена через `generate_world()` THEN система SHALL CONTINUE TO использовать все 8 этапов пайплайна (Command Interpretation, Semantic Planning, Scene Graph, Anchors, Constraints, Layout Solving, Physics Validation, Export)

3.6 WHEN экспортируется сцена в MuJoCo XML THEN система SHALL CONTINUE TO включать все свойства объектов (pose, size, is_static) в выходной файл

**4. LLM семантическое планирование**

3.7 WHEN LLM генерирует семантический план THEN система SHALL CONTINUE TO использовать `build_semantic_plan()` из `plan.py`

3.8 WHEN парсится семантический план THEN система SHALL CONTINUE TO использовать `SemanticPlanParser` для валидации и обработки

**5. Проверка физики**

3.9 WHEN включена физическая валидация (`enable_physics_validation=True`) THEN система SHALL CONTINUE TO проверять коллизии, стабильность стекирования и грузоподъемность

3.10 WHEN обнаружены проблемы физики THEN система SHALL CONTINUE TO использовать `validate_and_repair_layout()` для исправления
