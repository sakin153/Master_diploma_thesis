# Bugfix Requirements Document

## Introduction

Эта спецификация описывает исправление бага с коллизиями между объектами на одной поверхности. В текущей реализации объекты, размещенные на одной поверхности (например, две коробки на столе), пересекаются друг с другом. Система не обнаруживает или не корректно обрабатывает пересечения между объектами на одном уровне.

Проблема критична для создания реалистичных сцен для обучения роботов, так как пересекающиеся объекты нарушают физическую достоверность симуляции.

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN система размещает несколько объектов на одной поверхности (например, две коробки на столе) THEN объекты частично входят друг в друга (пересекаются)

1.2 WHEN проверка коллизий выполняется в `check_collisions()` в `physics.py` THEN проверка не обнаруживает пересечения между объектами на одном уровне или не применяет корректировки

1.3 WHEN `gradient_resolve_overlaps()` в `geometry.py` вызывается для разрешения пересечений THEN функция не устраняет пересечения между объектами на одной поверхности

1.4 WHEN `validate_and_repair_layout()` в `physics.py` выполняет валидацию THEN пересечения между объектами на одном уровне не исправляются

### Expected Behavior (Correct)

2.1 WHEN система размещает несколько объектов на одной поверхности THEN она SHALL проверять коллизии между объектами с использованием OBB (Oriented Bounding Box)

2.2 WHEN обнаружена коллизия между объектами на одном уровне THEN система SHALL скорректировать позиции объектов, чтобы устранить пересечение

2.3 WHEN используется `check_collisions()` в `physics.py` THEN функция SHALL корректно обнаруживать пересечения между объектами на одном уровне с учетом их размеров и ориентации

2.4 WHEN `gradient_resolve_overlaps()` вызывается для разрешения пересечений THEN функция SHALL итеративно разводить пересекающиеся объекты до устранения коллизий

2.5 WHEN `validate_and_repair_layout()` выполняет валидацию THEN все пересечения между объектами на одном уровне SHALL быть устранены

2.6 WHEN алгоритмическое разрешение коллизий не может найти решение (например, слишком много объектов на маленькой поверхности) THEN система SHALL использовать LLM для определения оптимального размещения объектов

2.7 WHEN LLM используется для разрешения коллизий THEN он SHALL получать контекст: список объектов с размерами, текущие позиции, семантические ограничения, и размеры поверхности

2.8 WHEN LLM предлагает новые позиции объектов THEN система SHALL валидировать предложенные позиции и применять их только если они устраняют коллизии и соблюдают ограничения

### Unchanged Behavior (Regression Prevention)

3.1 WHEN объекты размещены на разных уровнях (например, коробка на столе и стол на полу) THEN система SHALL CONTINUE TO не применять разделение по XY между объектами на разных уровнях

3.2 WHEN объекты имеют семантические ограничения (например, "near", "on_top_of") THEN система SHALL CONTINUE TO соблюдать эти ограничения при разрешении коллизий

3.3 WHEN объекты размещены в пределах комнаты THEN система SHALL CONTINUE TO удерживать объекты в границах комнаты после разрешения коллизий

3.4 WHEN проверка коллизий выполняется для объектов с разными размерами THEN система SHALL CONTINUE TO корректно учитывать размеры объектов при обнаружении пересечений

3.5 WHEN `_z_intervals_overlap()` проверяет объекты на разных высотах THEN функция SHALL CONTINUE TO корректно определять, что объекты находятся на разных уровнях

3.6 WHEN алгоритмическое разрешение коллизий успешно устраняет пересечения THEN система SHALL CONTINUE TO не вызывать LLM (LLM используется только как fallback)

3.7 WHEN система использует существующие функции (`model_to_obb()`, `obb_overlap()`) THEN эти функции SHALL CONTINUE TO работать корректно для обнаружения коллизий
