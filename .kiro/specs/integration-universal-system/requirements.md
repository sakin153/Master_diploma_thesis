# Требования: Замена старой системы на Universal Placement System

## Обзор

**Полностью заменить** существующую систему генерации сцен на Universal Placement System. Создать одну функцию `generate_world(query, ...)` которая принимает текстовый промпт и возвращает путь к MuJoCo XML файлу.

## Цели

1. **Полная замена** - Удалить legacy placement (`solve_floor_placements`, `solve_wall_placements`, `solve_small_object_placements`)
2. **Простой API** - Одна функция `generate_world(query, ...)` для вызова из `main.py`
3. **Только MuJoCo XML** - Экспорт только в MuJoCo формат
4. **Использовать LLM** - Сохранить LLM для извлечения объектов и семантического планирования
5. **Использовать EmbodiedGen** - Работать с существующими моделями из датасета

## Функциональные требования

### FR-1: Простой API

**FR-1.1** Одна функция `generate_world()` в `creator/runner.py`:
```python
def generate_world(
    query: str,
    cache_dir: Optional[str] = None,
    assets_dir: Optional[str] = None,
    seed: int = 42,
) -> str:
    """Генерация 3D сцены из текстового описания.
    
    Args:
        query: Текстовое описание сцены (например, "стол и стул")
        cache_dir: Директория для кэша (опционально)
        assets_dir: Директория с моделями (опционально, по умолчанию HuggingFace)
        seed: Random seed для воспроизводимости
    
    Returns:
        Путь к сгенерированному MuJoCo XML файлу
    """
```

**FR-1.2** Функция должна быть вызываема из `main.py`:
```python
world_path = generate_world(query="стол и стул", seed=42)
```

**FR-1.3** Функция должна возвращать путь к MuJoCo XML файлу

### FR-2: Пайплайн генерации

**FR-2.1** Пайплайн должен состоять из этапов:
1. **Извлечение объектов** - LLM извлекает список объектов из промпта
2. **Подбор моделей** - Поиск моделей в EmbodiedGen датасете
3. **Загрузка моделей** - Загрузка 3D моделей и получение размеров
4. **Размещение** - Universal Placement System размещает объекты
5. **Экспорт** - Генерация MuJoCo XML
6. **Сохранение** - Сохранение файла и метаданных

**FR-2.2** Система должна использовать существующие компоненты:
- `EmbodiedGenLoader` - загрузка моделей
- `MujocoSimInterface` - работа с MuJoCo
- `prompt_model` - LLM для извлечения объектов
- `Cache` - кэширование

**FR-2.3** Система должна использовать Universal Placement System:
- `UniversalPlacementSystem.generate_scene()` для размещения
- Все 11 компонентов (SceneGraph, AnchorSystem, и т.д.)

### FR-3: Извлечение объектов через LLM

**FR-3.1** Система должна использовать LLM для извлечения объектов:
- Промпт: "Какие объекты нужны для сцены: {query}"
- Ответ: список объектов с количеством
- Пример: "стол и два стула" → ["table", "chair", "chair"]

**FR-3.2** Система должна подбирать модели из EmbodiedGen:
- Поиск по имени объекта
- Ранжирование по релевантности
- Выбор лучшего совпадения

**FR-3.3** Система должна передавать промпт в Universal System:
- Universal System использует CommandInterpreter для парсинга
- Автоматическое извлечение пространственных ограничений
- Построение Scene Graph

### FR-4: Экспорт в MuJoCo XML

**FR-4.1** Система должна генерировать MuJoCo XML:
- Использовать `MujocoSimInterface.add_models()`
- Правильная физика (массы, коллизии)
- Статические и динамические объекты

**FR-4.2** Система должна сохранять файл:
- Путь: `{cache_dir}/worlds/scene_latest.xml`
- Сохранение метаданных в TinyDB
- Генерация preview изображений (опционально)

**FR-4.3** Удалить поддержку других форматов:
- ~~USD~~
- ~~glTF~~
- ~~JSON~~ (только для отладки, опционально)

### FR-5: Удаление legacy кода

**FR-5.1** Удалить старые функции размещения:
- `solve_floor_placements()`
- `solve_wall_placements()`
- `solve_small_object_placements()`
- Связанный код в `floor_solver.py`, `wall_solver.py`, `small_objects.py`

**FR-5.2** Удалить неиспользуемые компоненты:
- Старый constraint solver (если есть)
- Старый layout solver (если есть)
- Дублирующийся код

**FR-5.3** Упростить `runner.py`:
- Убрать условные ветвления
- Убрать fallback логику
- Оставить только новую систему

### FR-6: Валидация (опционально)

**FR-6.1** Физическая валидация встроена в Universal System:
- Проверка коллизий (OBB + SAT)
- Проверка стабильности стекирования
- Автоматическое восстановление после ошибок

**FR-6.2** VLM валидация (опционально, можно оставить):
- Если `vlm_validation=True` → использовать существующий `validate_and_repair_loop()`
- Если `vlm_validation=False` → пропустить

**FR-6.3** Preview рендеринг (опционально):
- Генерация изображений сцены
- Сохранение в cache директорию

### FR-7: Производительность

**FR-7.1** Система должна работать приемлемо:
- Размещение 10 объектов: < 10 секунд
- Размещение 20 объектов: < 30 секунд
- Размещение 50 объектов: < 2 минут

**FR-7.2** Оптимизация не критична на первом этапе:
- Можно оптимизировать позже
- Главное - корректность работы

## Нефункциональные требования

### NFR-1: Надежность

**NFR-1.1** Система должна обрабатывать ошибки gracefully:
- Логирование всех ошибок
- Понятные сообщения об ошибках
- Fallback на legacy систему при критических ошибках

**NFR-1.2** Система должна быть стабильной:
- Детерминированность при одинаковом seed
- Отсутствие memory leaks
- Корректная очистка ресурсов

### NFR-2: Поддерживаемость

**NFR-2.1** Код должен быть чистым:
- Следование PEP 8
- Типизация (type hints)
- Документация (docstrings)

**NFR-2.2** Код должен быть тестируемым:
- Unit тесты для новых компонентов
- Интеграционные тесты для пайплайна
- Регрессионные тесты для совместимости

**NFR-2.3** Код должен быть расширяемым:
- Модульная архитектура
- Четкие интерфейсы
- Возможность добавления новых компонентов

### NFR-3: Совместимость

**NFR-3.1** Система должна работать с существующими компонентами:
- EmbodiedGenLoader
- MujocoSimInterface
- VLM validator
- Cache system

**NFR-3.2** Система должна сохранять API:
- `generate_world()` signature не меняется
- Добавление опциональных параметров
- Обратная совместимость результатов

**NFR-3.3** Система должна работать на всех платформах:
- Linux (основная)
- macOS
- Windows (опционально)

## Ограничения

### C-1: Технические ограничения

**C-1.1** Система должна использовать Python 3.10+

**C-1.2** Система должна работать с существующими зависимостями:
- MuJoCo
- NumPy
- TinyDB
- Hypothesis (для тестов)

**C-1.3** Система не должна требовать GPU

### C-2: Функциональные ограничения

**C-2.1** Система работает только с 2D размещением (XY plane):
- Z координата определяется автоматически
- Поддержка стекирования по Z

**C-2.2** Система поддерживает только прямоугольные комнаты:
- Произвольные полигональные комнаты - опционально
- L-образные комнаты - опционально

**C-2.3** Система не поддерживает динамическую симуляцию:
- Только статическое размещение
- Физическая валидация без симуляции
