  Общая архитектура
  
  Это система генерации физически корректных 3D-сцен для MuJoCo на основе текстовых запросов. Проект использует 7-стадийный пайплайн:
  
  Стадии генерации:
  
  1. Расширение промпта (prompt_expander.py) - короткий запрос → детальная спецификация сцены (тип комнаты, стиль, размеры)
  2. Извлечение объектов (runner.py) - LLM выбирает объекты из каталога Objaverse
  3. Загрузка моделей и масштабирование (mujoco.py) - скачивание GLB/OBJ, вычисление OBB, нормализация до реальных размеров
  4. Определение размера комнаты (room_planner.py) - расчет размеров на основе площади объектов × коэффициент циркуляции
  5. Семантическое планирование (plan.py) - LLM генерирует JSON с ограничениями (on_floor, against_wall, near и т.д.) + граф сцены
  6. Решение размещения (placement/) - beam-search для размещения на полу + размещение на стенах + размещение мелких объектов на поверхностях
  7. Физическая валидация (engine_refine.py) - симуляция MuJoCo (0.5-2.0 сек) для устранения проникновений
  8. VLM валидация (опционально, vlm_validator.py) - проверка через vision-модель, итеративное исправление
  
  Ключевые технические решения:
  
  Алгоритм размещения (placement/floor_solver.py):
  
  - OBB + SAT для обнаружения коллизий (вдохновлено ImperativeScene)
  - Многокритериальная функция потерь: inbound + overlap + clearance + constraint satisfaction
  - DFS + beam search с сортировкой по размеру (largest-first)
  - Адаптивная генерация кандидатов: регулярная сетка + jitter + смещение к целевым объектам
  - Градиентное разрешение перекрытий (post-pass)
  
  Типы ограничений:
  
  - on_floor, against_wall, wall_mounted
  - near, far, left_of, right_of, in_front_of, behind
  - face_to, center_aligned
  
  Масштабирование объектов:
  
  Жестко закодированные таблицы высот по категориям в mujoco.py:
  
  - cup=0.11м, desk=0.75м, wardrobe=2.0м и т.д.
  - Также ограничения на горизонтальные размеры (plate≤0.32м, phone≤0.08м)
  
  LLM интеграция:
  
  - Ollama локально (http://localhost:11434)
  - Модель: deepseek-v3.1:671b-cloud
  - SQLite кэш промптов в $CACHE_DIR/.ollama_cache.sqlite3
  
  Структура модулей:
  
  creator/
  ├── runner.py              # Главный пайплайн
  ├── llm/model.py           # Обертка Ollama с кэшем
  ├── model_databases/       # Загрузчики каталогов (Objaverse, EmbodiedGen)
  ├── scene/                 # Расширение промпта, граф сцены, валидация
  ├── placement/             # Алгоритмы размещения (floor/wall/small objects)
  │   ├── floor_solver.py    # DFS+beam для пола
  │   ├── wall_solver.py     # Размещение на стенах
  │   ├── small_objects.py   # Размещение на поверхностях
  │   ├── geometry.py        # OBB, SAT, AABB примитивы
  │   └── constraint_validation.py  # Проверка и исправление ограничений
  ├── sim_interfaces/mujoco.py  # Загрузка моделей, нормализация, сборка XML
  ├── postprocess/engine_refine.py  # Физическая симуляция
  └── contexts_prompts/      # Шаблоны промптов для LLM
  
  Текущие проблемы (из task.txt):
  
  1. ✅ Список объектов генерируется - реализовано
  2. ❌ Неправильное положение объектов - объекты проходят через пол или висят в воздухе
  3. ❓ Нужна интеграция Mujoco scene editor для редактирования
  
  Сильные стороны:
  
  - Продуманная архитектура с четким разделением стадий
  - Использование лучших практик из исследовательских проектов
  - Физическая валидация через MuJoCo
  - Кэширование LLM-запросов
  - Поддержка сложных пространственных ограничений
  
  Слабые стороны:
  
  - Жестко закодированные размеры объектов (не масштабируется)
  - Проблемы с точностью размещения (проникновения через пол)
  - Нет интерактивного редактора
  - Зависимость от локального Ollama
  - Отсутствие тестов
  
  Рекомендации:
  
  1. Исправить размещение объектов: улучшить физическую валидацию, добавить проверку контакта с полом
  2. Динамическое определение размеров: использовать VLM вместо жестких таблиц
  3. Интеграция редактора: добавить Mujoco scene editor для ручной коррекции
  4. Улучшить beam search: добавить больше эвристик для избежания коллизий
  5. Добавить тесты: особенно для геометрических примитивов и размещения
  
  Проект находится на хорошем уровне для MVP, но требует доработки алгоритма размещения и валидации.
