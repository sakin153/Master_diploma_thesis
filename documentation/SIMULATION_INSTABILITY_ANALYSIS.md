## 🎯 ОСНОВНАЯ ПРИЧИНА (проверено 3 раза)

### **Проблема #1: Коробки имеют 23 отдельных collision mesh'а**

Каждая коробка в сцене представлена **одним телом (body)**, но внутри этого тела находится **23 отдельных collision geometry** (строки 15-37 в XML файле коробки):

```xml
<!-- Файл: 0626293c5f3e591b9df5fe282051c4cd_1.xml -->
<body name="0626293c5f3e591b9df5fe282051c4cd_1">
  <!-- 1 визуальный mesh -->
  <geom material="material_2" mesh="..." class="visual1" />
  
  <!-- 23 collision mesh'а для физики! -->
  <geom mesh="..._collision_0" density="50.0" />
  <geom mesh="..._collision_1" density="50.0" />
  <geom mesh="..._collision_2" density="50.0" />
  ...
  <geom mesh="..._collision_22" density="50.0" />
</body>
```

**Почему это проблема:**
- Каждый из 23 mesh'ей может создавать контакты с бананами/яблоками
- При падении мелких объектов внутрь коробки, они одновременно контактируют с 5-10 разными mesh'ами
- MuJoCo solver пытается разрешить все эти контакты одновременно
- Возникают конфликтующие constraint'ы (один mesh толкает вверх, другой вниз)
- Результат: численная нестабильность и velocity explosions

### **Проблема #2: Мелкие объекты (бананы/яблоки) размещены ВНУТРИ коробок**

Из `stage3_final_layout_20260511_131556.json`:

**Коробка #1** (y=-0.55, z=0.945):
- 5 бананов размещены на z=1.154 (на 0.21м ВЫШЕ дна коробки)
- Бананы висят в воздухе внутри коробки

**Коробка #2** (y=0.55, z=0.945):
- 5 яблок размещены на z=1.175 (на 0.23м ВЫШЕ дна коробки)
- Яблоки висят в воздухе внутри коробки

### **Проблема #3: Размеры не учитывают реальную геометрию**

Коробка:
- Высота по JSON: 0.35м
- Дно коробки: z=0.945м
- Верх коробки: z=0.945 + 0.175 = 1.12м

Бананы размещены на z=1.154м - это **ВЫШЕ верха коробки**!

## ✅ РЕШЕНИЯ (в порядке приоритета)

### 🔧 Решение #1: Упростить collision geometry коробок
```python
# В mujoco_assembler.py или model_loader.py
# Заменить 23 mesh'а на один простой box collider:
<geom type="box" size="0.3075 0.175 0.3135" density="50.0" />
```

### 🔧 Решение #2: Правильно размещать объекты "in" контейнерах
```python
# В scene_planner.py, функция размещения "in" relationship:
# Текущий код размещает на: parent_z + parent_height/2 + child_height/2
# Должно быть: parent_z + (parent_height/2 - container_depth) + child_height/2

# Для открытой коробки:
container_depth = parent_height * 0.8  # 80% высоты - это глубина
placement_z = parent_z + (parent_height/2 - container_depth) + child_height/2
```

### 🔧 Решение #3: Добавить проверку penetration перед симуляцией
```python
def check_initial_penetration(models):
    """Проверить, что объекты не пересекаются изначально"""
    for i, obj1 in enumerate(models):
        for obj2 in models[i+1:]:
            if objects_overlap(obj1, obj2):
                raise ValueError(f"Initial penetration: {obj1} and {obj2}")
```

### 🔧 Решение #4: Использовать более мягкие contact параметры
```xml
<!-- Для мелких объектов в контейнерах -->
<geom ... solref="0.02 1.0" solimp="0.95 0.99 0.001 0.5 2" />
```
