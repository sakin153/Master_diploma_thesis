# Оптимизация контекста при размещении объектов

## Проблема

При размещении объектов в больших сценах (например, "3 стола, на каждом 2 коробки, в каждой 3 яблока" = 27 объектов), LLM получал информацию о **всех** уже размещенных объектах.

### Пример: размещение последнего яблока (объект #27)

**ДО оптимизации:**
```
world_state содержал:
- 3 стола (позиции, размеры, границы)
- 6 коробок (позиции, размеры, границы)  
- 26 яблок (позиции, размеры, границы)

Итого: ~35 строк × ~150 символов = ~5250 символов
```

**Проблемы:**
1. Избыточная информация - яблоку в коробке_1 не нужно знать о столах и других коробках
2. Большой размер промпта - замедляет LLM и увеличивает стоимость
3. Шум в контексте - LLM может запутаться в нерелевантной информации

## Решение

Фильтрация объектов по иерархии - передавать только **релевантные** объекты:

### Логика фильтрации

При размещении объекта показываем только:
1. **Прямого родителя** (например, коробку для яблока)
2. **Siblings** - объекты с тем же родителем (другие яблоки в той же коробке)
3. **Объекты того же уровня** (для якорных объектов - другие якоря)

### Пример: размещение яблока в коробке_1_стола_1

**ПОСЛЕ оптимизации:**
```
world_state содержит только:
- коробка_1_стола_1 (родитель)
- 2 других яблока в этой же коробке (siblings)

Итого: ~3 строки × ~150 символов = ~450 символов
```

**Экономия: ~90% размера контекста!**

## Реализация

### Модифицированная функция `_ws_summary()`

```python
def _ws_summary(world_state, current_node=None):
    """Generate summary of placed objects, optionally filtered by hierarchy.
    
    Args:
        world_state: Current world state with placed objects
        current_node: Optional node being placed. If provided, only shows:
                     - Objects at the same hierarchy level (siblings)
                     - Direct parent
                     - Direct children of parent (siblings)
    """
    # Фильтрация по иерархии
    if current_node is not None:
        relevant_objects = []
        current_parent_id = current_node.get("parent_id")
        
        for p in placed:
            # Включаем родителя
            if current_parent_id and obj_id.startswith(current_parent_id + "_inst_"):
                relevant_objects.append(p)
            
            # Включаем siblings (объекты с тем же родителем)
            if shares_same_parent(p, current_node):
                relevant_objects.append(p)
```

### Использование

Функция автоматически применяется при вызове:

```python
world_state=_ws_summary(world_state, current_node=node)
```

## Результаты

### Сравнение размеров контекста

| Сцена | Объектов | ДО (символов) | ПОСЛЕ (символов) | Экономия |
|-------|----------|---------------|------------------|----------|
| 3 стола | 3 | 450 | 300 | 33% |
| 3 стола + 6 коробок | 9 | 1350 | 450 | 67% |
| 3 стола + 6 коробок + 18 яблок | 27 | 4050 | 450 | 89% |
| 10 столов + 40 стульев | 50 | 7500 | 600 | 92% |

### Преимущества

1. **Скорость** - меньше токенов = быстрее генерация
2. **Стоимость** - меньше токенов = дешевле API вызовы
3. **Качество** - меньше шума = лучше фокус LLM
4. **Масштабируемость** - можно создавать сцены с сотнями объектов

### Обратная совместимость

Если `current_node=None`, функция возвращает все объекты (старое поведение).
