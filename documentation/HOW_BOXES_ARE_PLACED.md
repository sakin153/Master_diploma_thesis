# Как ставятся коробки на столы

## Запрос пользователя
```
"3 Больших деревяных стола, на каждом столе 2 коробки, в каждой коробке по 3 яблока"
```

## Процесс размещения

### Этап 1: Построение иерархии (Scene Graph)

LLM анализирует запрос и создает **граф зависимостей**:

```json
{
  "nodes": [
    {
      "id": "tables",
      "model_name": "table",
      "instances": 3,           // ← 3 стола
      "parent_id": null,        // ← Якорный объект (нет родителя)
      "level": 0
    },
    {
      "id": "boxes",
      "model_name": "box",
      "instances": 6,           // ← 6 коробок (2 на каждый стол)
      "parent_id": "tables",    // ← Родитель: столы
      "relationship": {
        "type": "on_surface",   // ← Тип: на поверхности
        "arrangement": "auto"
      },
      "level": 1
    },
    {
      "id": "apples",
      "model_name": "apple",
      "instances": 18,          // ← 18 яблок (3 в каждой коробке)
      "parent_id": "boxes",     // ← Родитель: коробки
      "relationship": {
        "type": "in",           // ← Тип: внутри
        "arrangement": "auto"
      },
      "level": 2
    }
  ]
}
```

**Иерархия:**
```
Level 0: tables (3 экземпляра)
    ↓
Level 1: boxes (6 экземпляров, parent_id="tables")
    ↓
Level 2: apples (18 экземпляров, parent_id="boxes")
```

---

### Этап 2: Размещение по уровням

#### 2.1. Размещение столов (Level 0)

**Запрос к LLM:** "Разместить 3 стола в комнате"

**Результат:**
```python
# Один LLM запрос для всех 3 столов
table_1: pos=(-1.8, 0.0, 0.5)  # Левый стол
table_2: pos=(0.0, 0.0, 0.5)   # Центральный стол
table_3: pos=(1.8, 0.0, 0.5)   # Правый стол
```

---

#### 2.2. Размещение коробок (Level 1)

**Ключевой момент:** Коробки размещаются **НЕ все сразу**, а **по группам для каждого стола**!

Система видит:
- `boxes.instances = 6` (всего 6 коробок)
- `boxes.parent_id = "tables"` (родитель: столы)
- `tables.instances = 3` (3 родителя)

**Логика:** 6 коробок ÷ 3 стола = **2 коробки на каждый стол**

**Размещение происходит в 3 запроса:**

##### Запрос 1: Коробки на столе_1
```python
# LLM получает контекст:
# - Родитель: table_1 at (-1.8, 0.0, 0.5), size=(1.4m × 1.8m × 1.0m)
# - Задача: разместить 2 коробки на этом столе
# - Relationship: type="on_surface"

# LLM решает:
box_1: pos=(-1.8, -0.6, 1.12)  # Левая коробка на столе_1
box_2: pos=(-1.8, +0.6, 1.12)  # Правая коробка на столе_1
```

##### Запрос 2: Коробки на столе_2
```python
# LLM получает контекст:
# - Родитель: table_2 at (0.0, 0.0, 0.5)
# - Задача: разместить 2 коробки на этом столе

box_3: pos=(0.0, -0.325, 1.12)  # Левая коробка на столе_2
box_4: pos=(0.0, +0.325, 1.12)  # Правая коробка на столе_2
```

##### Запрос 3: Коробки на столе_3
```python
# LLM получает контекст:
# - Родитель: table_3 at (1.8, 0.0, 0.5)
# - Задача: разместить 2 коробки на этом столе

box_5: pos=(1.8, -0.68, 1.12)  # Левая коробка на столе_3
box_6: pos=(1.8, -0.18, 1.12)  # Правая коробка на столе_3
```

---

#### 2.3. Размещение яблок (Level 2)

Аналогично, яблоки размещаются **по группам для каждой коробки**:

- 18 яблок ÷ 6 коробок = **3 яблока в каждой коробке**
- **6 отдельных LLM запросов** (по одному для каждой коробки)

**Пример для box_1:**
```python
# LLM получает контекст:
# - Родитель: box_1 at (-1.8, -0.6, 1.12), size=(0.39m × 0.4m × 0.22m)
# - Задача: разместить 3 яблока ВНУТРИ этой коробки
# - Relationship: type="in"

apple_1: pos=(-1.8, -0.686, 1.28)  # Яблоко 1 в box_1
apple_2: pos=(-1.8, -0.600, 1.28)  # Яблоко 2 в box_1
apple_3: pos=(-1.8, -0.514, 1.28)  # Яблоко 3 в box_1
```

## Количество LLM запросов

### Для сцены "3 стола + 6 коробок + 18 яблок":

1. **Построение графа:** 3 запроса
   - Phase A: CLASSIFY_HIERARCHY (1 запрос)
   - Phase B: ANCHOR_RELATIONS (1 запрос)
   - Phase C: GROUP_RELATIONS для tables (1 запрос)

2. **Размещение столов:** 1 запрос
   - Все 3 стола размещаются вместе

3. **Размещение коробок:** 3 запроса
   - Запрос 1: 2 коробки на table_1
   - Запрос 2: 2 коробки на table_2
   - Запрос 3: 2 коробки на table_3

4. **Размещение яблок:** 6 запросов
   - По 1 запросу для каждой коробки (3 яблока в каждой)

**Итого: ~13 LLM запросов**

## Преимущества такого подхода

### 1. **Контекстная осведомленность**
LLM знает точные размеры и позицию конкретного стола при размещении коробок:
```python
# При размещении коробок на table_2, LLM видит:
Parent: table_2 at (0.0, 0.0, 0.5)
Size: 1.4m × 1.8m × 1.0m
Surface bounds: x ∈ [-0.7..0.7], y ∈ [-0.9..0.9]
```

### 2. **Автоматическое распределение**
Система автоматически понимает:
- 6 коробок ÷ 3 стола = 2 коробки на стол
- 18 яблок ÷ 6 коробок = 3 яблока в коробке

### 3. **Масштабируемость**
Легко изменить запрос:
- "5 столов, на каждом 3 коробки" → 15 коробок, 5 запросов для коробок
- "10 столов, на каждом 1 коробка" → 10 коробок, 10 запросов для коробок

### 4. **Точность размещения**
Каждая коробка размещается с учетом:
- Размеров конкретного стола
- Уже размещенных коробок на этом столе (siblings)
- Границ поверхности стола

## Код, отвечающий за это

### Функция `_place_node()` в `scene_planner.py`

```python
def _place_node(node, world_state, query, llm_fn):
    # Проверяем, есть ли несколько родителей
    parent_id = node.get("parent_id")
    parents = _ws_find_all_by_node(world_state, parent_id)
    
    # Если родителей несколько И их количество = количеству детей
    if len(parents) > 1 and len(parents) == instances:
        # Распределяем детей по родителям
        children_per_parent = instances // len(parents)
        
        # Для каждого родителя размещаем его группу детей
        for parent_obj in parents:
            sub_node = dict(node)
            sub_node["instances"] = children_per_parent
            sub_node["_single_parent_override"] = parent_obj  # ← Привязка к конкретному родителю
            
            # Размещаем группу детей на этом родителе
            _place_node_batch(sub_node, world_state, query, llm_fn)
```

### Ключевая логика:

1. **Обнаружение паттерна:** `len(parents) == instances` (6 коробок, 3 стола → не равно)
2. **Распределение:** `children_per_parent = 6 // 3 = 2`
3. **Привязка:** `_single_parent_override` привязывает группу к конкретному столу
4. **Размещение:** Отдельный LLM запрос для каждой группы

## Оптимизация контекста

С нашей оптимизацией, при размещении коробок на table_2, LLM видит только:
- **table_2** (родитель)
- **2 коробки на table_2** (siblings)

**НЕ видит:**
- table_1 и table_3
- Коробки на других столах
- Яблоки

**Экономия:** ~90% размера контекста!
